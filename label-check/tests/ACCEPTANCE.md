# OCR 验收测试说明

运行：

```powershell
python -m tests.acceptance_eval --output tests/acceptance_report.json
python -m unittest discover -s tests -v
```

人工真值在 `fixtures/acceptance_annotations.json`。目前只标注了龙井厚乳 43 g 包装的营养表及 9 条置信度抽样行；`front_accurate.json` 是此前实际调用百度 OCR 保存的响应。本测试离线复现，不上传图片，也不消耗接口额度。另一张原味咸甜 72 g 设计图是**不同产品**，尚无配套 OCR 响应和人工逐项标注，不能并入该样本。

## 指标口径

| 指标 | 计分方法 | 当前验收边界 |
|---|---|---|
| 数字识别准确率 | 对每张图人工标注的营养表数字格逐格比较。通过结构化字段追溯到 OCR 原始行，再提取原始行的数字；缺失、错位或错字均算错。`正确数字格 / 标注数字格`。 | 目标 ≥98%，且要求 **50 张不同的含数字标签图**。不足 50 张时结果为 `insufficient_samples`，即使当前准确率达标也不宣称通过。 |
| 结构化解析成功率 | 表头基准、每份量、营养素行、数值、单位、NRV% 与人工真值全部一致才算一张表成功。`完整正确的表 / 标注的表`。 | 目标 ≥95%。当前仅 1 张表，报告中的 `observedStatus` 只反映这张表，不代表大样本验收。 |
| 置信度准确性 | 抽取 OCR 行，由人判断该行是否需要复核，与 `<0.96` 的自动标记比较，报告一致率、误送复核数和漏送复核数。 | 验收表未给数值阈值；脚本以“样本全部一致”作为严格判定，同时保留每条分歧供人工讨论。 |

数字识别的当前标注范围是**营养表的 15 个数字格**，不是整张包装上所有数字。原始图片上的数字真值由人工目视转录；OCR 响应本身不能充当真值。`evidenceId` 仅用于定位，计分按字段角色追溯原始 OCR 行，所以同一数字写在错误行也不能轻易过关。

## 当前结果与继续验收

本次样图的数字格为 15/15，营养表为 1/1；改为 `0.96` 后，既有 9 条置信度抽样与人工标注全部一致。这个结果只覆盖一张图片和少量抽样行，尚不能证明普遍表现。要证明 50 图指标，继续向标注文件增加**真实、不同**的标签图片、对应 OCR 响应、营养表真值和抽样人工判断，再运行同一脚本。文件路径相同或内容相同的图片不会被重复计数。

截图中的 NRV 计算和数字矛盾指标属于后续模块，当前项目尚未实现，不能用本 OCR 测试报告声称通过整张验收表。
