# 通用营养表 OCR 与结构化方案（设计稿）

本方案仅设计 OCR 和结构化阶段，不计算 NRV%，不作合规结论。保留现有 Python `LabelDocument` 接口作为下游输入。课程要求 50 张含数字标签图验证数字识别、营养表结构化，并支持中文、英文等常见语言；题面没有承诺固定厂商或固定版式。

## 核心决定

**通用文字 OCR 负责包装全文和逐行文字；表格文字识别 V2 负责营养表的区域、单元格及行列关系；确定性代码负责字段语义、单位、基准和证据核对；视觉模型只处理仍有歧义的布局候选；人工只处理无法确认的关键字段。** 任何单个服务的返回都不能直接当作已确认的合规事实。

50 张现有样本的审计显示：29 张没有生成营养表、49 条已生成行中 18 条缺含量、25 条缺 NRV%，并有高置信度的邻行和跨表错配。主因是现有代码采用标题附近固定的 450/115 像素范围以及 25 像素配行阈值。因此无需针对每个厂商写模板，必须换成“先识别表格结构、后解释单元格”的通用流程。

```text
原图
 ├─ 通用高精度含位置 OCR → 全文 evidence（产品信息、配料、宣称、表格文字）
 └─ 营养表候选区域 → 表格文字识别 V2 → table_location + body(row/col/words)
                                   ↓
                       单元格网格 + 列角色/表头基准识别
                                   ↓
                    与通用 OCR 逐格交叉核对；必要时局部重识别
                                   ↓
                    LabelDocument + 文档/字段复核项
                                   ↓
                        仍有歧义 → 视觉模型候选 → 人工复核
```

## 1. 两种 OCR 如何调用

1. 现有 `recognize_accurate` 继续识别整张包装图，返回文字、原图坐标和行级 `probability.average`。它适合配料、宣称、产品名，也作为表格数值的独立核对来源。原始响应单独保留，不能被合并结果覆盖。
2. 用标题、`项目`/`每100`/`NRV`、`Nutrition Facts` 等线索，在原图上生成**宽松的候选表格区域**。窗口大小根据附近文字高度和图像尺寸估算，不使用固定的 450 像素。找不到线索时仍需尝试全图或有重叠的图块，避免“零表即零复核”。每个候选裁图需保存原图偏移、缩放/旋转变换和 SHA-256。
3. 对候选裁图调用表格文字识别 V2，采用当前文档的 `POST /rest/2.0/ocr/v1/table`，发送 Base64 图像、`cell_contents=true`、`return_excel=false`。V2 支持多表格，返回 `tables_result[].table_location`，`body[]` 的 `cell_location`、`row_start/end`、`col_start/end`、`words`，以及可选的逐行文字位置 `contents[]`。它不是旧的异步表格接口。请求前检查 V2 的大小/像素限制；超限时优先裁图或分块，不牺牲细小数字的清晰度。
4. 将 V2 的四角点坐标经**逆变换还原到原图**。仅裁切时为 `原图坐标 = 裁图坐标 + 裁切左上角`；缩放/旋转后使用保存的变换矩阵。`boxPx` 可存四角点的外接矩形，但审计数据应保留原四角点，以便斜表格的精确高亮。

## 2. 从单元格转成营养表

- **先选对表**：每个 `tables_result` 是一个候选表，不是每个表都叫营养表。结合标题、表头、营养素名称、数值和参考值列识别营养表；配料说明、功效成分、促销表不得误入。含两张表或双列小表时，分开处理并保持各自的表格 ID。
- **按行列编号重建网格**：`row_start/end`、`col_start/end` 表示单元格占据的行列范围；先处理跨行跨列/合并表头，再把同一数据行的名称、含量、参考百分比分配到各列。禁止根据整张图中最近的文字框跨表拼接。
- **识别列角色而非固定列号**：通过表头和单元格内容识别 `nutrient`、`amount`、`referencePercent`，兼容表头缺失、列顺序变化、没有百分比列和左右并列两组项目。列角色不唯一时进入 `needs_review`，不可随便选第一列。
- **解析基准**：从表头提取 `per_100g`、`per_100ml`、`per_serving` 和每份量。读取不到时使用 `unknown`，后续计算不得假设为每 100g。
- **规范字段**：文字保留 `raw`，数值用十进制字符串，单位规范为 `kJ/g/mg/µg/%` 等；营养素使用中英同义词表映射到稳定代码。`%NRV` 与其他体系的 `%DV` 不可无条件当成同一种参考值；需要保存百分比体系或标为待确认。
- **缺格要区分**：原图确实留空、OCR 未读到、V2 未检出是三种不同情形。凡不能证明原图留空的关键数值，不应悄悄填 `null` 并视为完整表。

## 3. 两路结果如何核对和定状态

| 情况 | 处理 |
|---|---|
| V2 给出行列；对应单元格可与通用 OCR 的文字、位置匹配，数字/单位一致，通用 OCR 分数 ≥0.96，表格完整性检查通过 | 生成字段，`sourceRefs` 同时引用两路证据；通过验证后可为 `ready`。 |
| 通用 OCR 低于 0.96，即使 V2 与它一致 | 按现有约定标 `needs_review`；V2 结果辅助人工查看，不绕过阈值。 |
| V2 与通用 OCR 的数字或单位冲突 | `needs_review`，同时显示两个原文和同一原图区域；不得按分数或多数票自动改数字。 |
| 只有 V2 读到关键数字 | 先对单元格原图局部再跑高精度含位置 OCR；仍无可核对来源时转人工复核。 |
| V2 无表、表内行列不完整或多种配对均可能 | 尝试改进的几何解析/视觉模型输出候选；仍不确定时生成**表级复核项**。 |

V2 官方文档列出的返回字段没有与通用 OCR `probability.average` 同义的分数，因此**不能把 V2 的行列编号当作 96% 置信度，也不能伪造 `ocrConfidence`**。跨引擎一致性是独立的校验依据，不是校准后的“正确概率”。高分 OCR 仍可能把 NRV% 配到邻行，故 `ready` 还需通过表内行列唯一性、表格区域、单位和完整性检查。

## 4. `shared` 接口和复核队列的最小调整

- `Evidence.sourceType` 已预留 `baidu_table_v2`。V2 的单元格文字作为**新增证据**，有自己的 ID 和原图坐标；原有 `baidu_accurate` 证据不删除。V2 未提供可验证的分数时 `ocrConfidence=null`。保存原始 V2 响应及裁图变换，以便重放。
- 当前 `validation.py` 会把任何 OCR 来源的 `null` 分数视为不确定，必须改为**按来源分别验证**：通用 OCR 使用 0.96 阈值；V2 使用“与通用 OCR 同格一致且结构检查通过”的可审计核对记录，或保持待复核。不能仅为通过校验而放宽所有来源。
- 在 `LabelDocument` 增加可选的表级解析诊断（推荐新版本字段，例如 `tableDiagnostics[]`），记录候选表位置、使用的引擎、行数、缺格/冲突和 `sourceRefs`。字段级 `FieldValue` 的状态及证据引用继续供计算模块使用。
- `collect_review_items` 除 `needs_review` 字段，还要输出 `TABLE_NOT_FOUND`、`TABLE_INCOMPLETE`、`ENGINE_CONFLICT`、`MULTIPLE_TABLE_CANDIDATES` 等表级项目。现有人工复核页须支持补建缺失行/整表，而不仅是修改已有字段。人工确认仍生成新文档并保留原始两路输出。

## 5. 模块落点与实施顺序

1. `src/ocr/baidu.py` 抽出可复用的 token/POST；新增 `table_v2.py`（接口、错误处理、原始响应）。`regions.py` 负责候选裁图及逆坐标变换。
2. `table_grid.py` 把 V2 单元格重建为行列网格；`nutrition_parser.py` 负责选营养表、列语义、单位和基准；`reconcile.py` 负责两路文字与位置核对；`quality_gate.py` 负责完整性与冲突路由。保留当前 `parser.py` 中的非表格字段解析。
3. 更新 `shared/models.py`、`validation.py`、`CONTRACT.md`、复核队列和页面；`src/main.py` 串联两路 OCR，并支持用保存的两份原始 JSON 离线重放。先不把视觉模型的候选值写回 `evidence`；视觉模型只能协助定位、解释冲突，关键数字不经核对不能变 `ready`。
4. 用现有 50 张中的典型失败图做开发回归：整表漏检 `6954767420363`，邻行错配 `6946036500036`，跨区域错配 `6914973603394`，双列 `6972434755648`，中英混排及表头缺失样本。准备逐格人工真值；再用未参与调规则的图片报告数字格准确率、整表完全正确率、错误 `ready` 数量和人工复核量。现有 50 张已参与问题发现，不能直接称为未见测试集。
